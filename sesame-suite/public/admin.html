Intégration réservations

Récupérez automatiquement les réservations depuis n'importe quel système externe (PMS, moteur de réservation…) — client Sesame ou non. L'appel se fait depuis le serveur, pas depuis le navigateur : aucun problème de CORS ni de proxy à installer.

Modèle de connecteur
Réglages techniques par défaut du modèle — verrouillés pour éviter une modification accidentelle.
Réglages techniques avancés
Connexion
Correspondance des champs
Pour chaque champ, indiquez le chemin vers la valeur dans un élément du tableau retourné par la source (ex : guest.email pour {"guest":{"email":"..."}}). Les champs marqués * sont obligatoires.
Chambres (facilities)
Optionnel, mais recommandé : importez les chambres avec leurs codes exacts de la source externe. Le mapping "code chambre" des réservations ci-dessus ne peut retrouver la bonne chambre que si son code correspond exactement — sinon la réservation est quand même importée, simplement sans nom de chambre associé.
Correspondance des champs
Encodage NFC
Optionnel — bouton "Encoder NFC" sur l'écran de détail d'une réservation (panneau Réservations). Même connexion/auth que ci-dessus, sur un endpoint séparé qui prend UNE réservation en paramètre. Laissez le chemin vide tant que vous n'avez pas confirmé que la source externe expose bien un tel endpoint (ex: capture réseau — F12 → onglet Réseau — sur le produit réel pendant un encodage) : le bouton échoue alors avec un message explicite plutôt que d'appeler une URL non configurée.
Récupération QR / code d'accès
Optionnel — alimente l'onglet "Clé digitale" de l'espace client (QR code + code d'accès affichés au client). Même connexion/auth que ci-dessus, sur un endpoint séparé qui prend UNE réservation en paramètre. Laissez le chemin vide tant que vous n'avez pas confirmé cet endpoint côté source réelle : le client voit alors un QR de démonstration (non fonctionnel sur un vrai lecteur) plutôt qu'une erreur — pratique en démo/vente. Une fois le chemin renseigné, un échec de CET appel est en revanche affiché explicitement au client, jamais remplacé silencieusement par la démo.
Optionnel — si le code d'accès est renvoyé par un second appel distinct du QR (ex : API Sesame Technology, dont le passcode n'est pas dans la même réponse que le QR) : même connexion/méthode/format/paramètres que ci-dessus, sur un chemin différent. Ignoré si un code a déjà été trouvé ci-dessus.
Ouverture de porte à distance
Optionnel — bouton "Ouvrir la porte" du même onglet "Clé digitale". Laissez le chemin vide tant que vous n'avez pas confirmé cet endpoint côté source réelle : le client garde alors le bouton "Simuler l'ouverture" existant. Une fois configuré, un échec réel n'est jamais remplacé par un faux succès — une porte non ouverte doit rester visiblement non ouverte.
Mise à jour d'une réservation
Optionnel — répercute vers la source externe les changements de chambre et les annulations/réactivations faits depuis le panneau "Réservations". La réservation est toujours mise à jour ici quel que soit l'état de ce réglage ; laissez le chemin vide tant que vous n'avez pas confirmé qu'un tel endpoint existe côté source réelle.
Fréquence
S'applique uniquement aux réservations. Les chambres changent rarement — importez-les manuellement ci-dessus (au premier réglage, puis en cas de changement).
